# docker compose up --buildの流れE：Redisが起動する（6E）

`docs/06.md`のE（39〜54）を詳しくしたもの。

コードブロックの1行目に、抜き出したファイルと行番号を書いている。\
`docker-entrypoint.sh`は、`redis:8-alpine`のイメージの`/usr/local/bin/docker-entrypoint.sh`（今回のイメージのもの。タブは空白2つにしている）。

コードやログは、iPhoneの縦画面で読めるよう、改行やインデントを変えたり、一部を省いたりしている。

出力は、2026-11-27に手元で実行して取ったもの（Redis 8.10.3）。ログの時刻はUTC（日本時間の9時間前）。

## 全体像

redisのコンテナでは、PID 1が2回入れ替わってから、`redis-server`になる。

```text
PID 1: sh docker-entrypoint.sh redis-server ...（root）
 └ exec setpriv → PID 1: sh docker-entrypoint.sh ...
   （redisユーザー・capabilitiesなし）
    └ exec → PID 1: redis-server ...（redisユーザー）
```

- 1回目（root）：データのフォルダの所有者を直し、権限を落として自分を実行し直す（2章）。
- 2回目（redis）：umaskを決め、モジュールを引数に足して、`redis-server`に置き換わる（3章）。
- `redis-server`：設定を読み、AOFからデータを戻して、接続を受け付け始める（4章）。

## 1. 起動したとき

1. Dockerが、イメージの`Entrypoint`の`docker-entrypoint.sh`を、`compose.yaml`の`command:`を引数にして実行する（`docs/6D.md`の9）。
   - ユーザー：イメージに`USER`がないのでroot。
   - 作業フォルダ：イメージの`WorkingDir`の`/data`。
   - 環境変数：イメージの`PATH`と`REDIS_VERSION`だけ（`compose.yaml`に`environment:`がない）。
2. `/data`には`redis-data`ボリュームが付いている。\
   ボリュームが空なら、イメージの`/data`（中身のない`redis:redis`のフォルダ）の所有者がコピーされる。\
   新しいボリュームで試すと、`/data`は`redis redis`の持ち物になっていた。
3. スクリプトの1行目は`#!/bin/sh`。Alpineの`/bin/sh`はBusyBoxのsh。

## 2. docker-entrypoint.sh（1回目：root）

```sh
# docker-entrypoint.sh:2-4
set -e

SETPRIV="/bin/setpriv --reuid redis --regid redis \
--clear-groups"
```

（`SETPRIV=`の行は、引用符の中で折り返している）

4. `set -e`：失敗したコマンドがあれば、そこでスクリプトを終える。
5. `SETPRIV`：redisユーザーに切り替えるコマンド。権限の確認（11）と、切り替え（14）で使う。

### 最初の引数を確かめる

```sh
# docker-entrypoint.sh:95-102
if [ "${1#-}" != "$1" ] || [ "${1%.conf}" != "$1" ]; then
  set -- redis-server "$@"
fi
CMD=$(command -v "$1" 2>/dev/null || :)

if [ "$(readlink -f "$CMD")" \
    = '/usr/local/bin/redis-server' ]; then
  IS_REDIS_SERVER=1
fi
```

（最後の`if`は折り返している）

6. `${1#-}`は、最初の引数の先頭の`-`を1つ取ったもの。変わったなら`-`で始まる引数。\
   `${1%.conf}`は、末尾の`.conf`を取ったもの。変わったなら設定ファイルの名前。\
   どちらかなら、先頭に`redis-server`を足す。\
   そのため、`command: ["--appendonly", "yes"]`のように`redis-server`を省いても動く。
7. 今回の最初の引数は`redis-server`なので、そのまま。\
   `command -v`で`/usr/local/bin/redis-server`が見つかり、`IS_REDIS_SERVER=1`になる。\
   `readlink -f`を通すのは、`redis-check-aof`などが`redis-server`へのシンボリックリンクだから。
8. 2番目の引数が`-`で始まらなければ、設定ファイルとして`CONFIG`に入れる（108〜111行目）。\
   今回は`--appendonly`なので、`CONFIG`は空のまま。Redisは設定ファイルなしで、コマンドラインの引数だけで動く。

### データのフォルダの所有者を直す

```sh
# docker-entrypoint.sh:117-126
if [ "$IS_REDIS_SERVER" ] && [ -z "$SKIP_DROP_PRIVS" ] \
    && [ "$(id -u)" = '0' ] \
    && has_cap setuid && has_cap setgid; then
  if [ -z "$SKIP_FIX_PERMS" ]; then
    if [ "$IS_REDIS_SENTINEL" ]; then
      fix_config_perms "$CONFIG" rw
    else
      fix_data_dir_perms
      fix_config_perms "$CONFIG" r
    fi
  fi
```

（1行目は折り返している）

9. 条件は、`redis-server`の起動で、rootで動いていて、ユーザーを切り替える権限（capabilitiesの`setuid`・`setgid`）を持っていること。\
   Dockerの既定のcapabilitiesには両方が入っているので、ここに入る。\
   `compose.yaml`で`user:`を指定すると、rootでなくなるので、この部分（と下の切り替え）は丸ごと飛ばされる。

```sh
# docker-entrypoint.sh:37-46
fix_data_dir_perms() {
  unknown_file="$(find . -mindepth 1 -maxdepth 1 \
    -not \( -name \*.rdb -or \
      \( -type d -and -name appendonlydir \) \) \
    -print -quit)"
  if [ -z "$unknown_file" ]; then
    find . -print0 | fix_perms_and_owner rw
  else
    echo "Notice: Unknown file '$unknown_file' ..."
  fi
}
```

（コメントを省き、長い行を折り返している）

10. 作業フォルダ（`/data`）の直下に、`*.rdb`と`appendonlydir`以外のものがあれば、何も直さない（ユーザーが置いたファイルを勝手に変えないため）。\
    今回は`dump.rdb`と`appendonlydir`だけなので、直す処理に進む。
11. `fix_perms_and_owner`は、ファイルごとに「redisユーザーで読み書きできるか」を`$SETPRIV test -r ... -a -w ...`で確かめ、できないものだけを`chown redis`・`chmod u+rw`（フォルダは`u+rwx`）する。\
    今回はすべてredisの持ち物なので、何も変えない（何も出力されない）。\
    別のイメージで作ったボリュームなど、所有者が合わないときに効く。
12. `fix_config_perms "$CONFIG" r`は、`CONFIG`が空なので、何もせずに戻る。

### 権限を落として、自分を実行し直す

```sh
# docker-entrypoint.sh:128-139
CAPS_TO_KEEP=""
if has_cap sys_resource; then
  CAPS_TO_KEEP=",+sys_resource"
fi
exec $SETPRIV \
  --nnp \
  --inh-caps=-all$CAPS_TO_KEEP \
  --ambient-caps=-all$CAPS_TO_KEEP \
  --bounding-set=-all$CAPS_TO_KEEP \
  "$0" "$@"
```

（コメントは省略）

13. `sys_resource`はDockerの既定のcapabilitiesに入っていないので、`CAPS_TO_KEEP`は空。
14. `setpriv`のフラグ：
    - `--reuid redis --regid redis`：uidとgidをredis（999と1000）にする。
    - `--clear-groups`：補助グループを持たない。
    - `--nnp`：no_new_privsを立てる。この後は、setuidのプログラムを実行しても権限が上がらない。
    - `--inh-caps=-all`・`--ambient-caps=-all`：子に引き継ぐcapabilitiesをなくす。
    - `--bounding-set=-all`：capabilitiesの上限そのものを0にする。この後は、どうやってもcapabilitiesを取り戻せない。
    - `"$0" "$@"`：同じスクリプト（`$0`）を、同じ引数で実行し直す。
15. `exec`なので、PID 1のまま、redisユーザーのスクリプトに置き換わる。\
    動いている`redis-server`の`/proc/1/status`を見ると、こうなっている。

```text
Uid:        999  999  999  999
Gid:        1000 1000 1000 1000
Groups:
CapInh:     0000000000000000
CapPrm:     0000000000000000
CapEff:     0000000000000000
CapBnd:     0000000000000000
CapAmb:     0000000000000000
NoNewPrivs: 1
```

（webのPID 1は、uid 999で`CapEff`は0だが、`CapBnd`は`a80425fb`、`NoNewPrivs`は0。`docs/6D.md`の16）

## 3. docker-entrypoint.sh（2回目：redis）

16. 2回目はuidが0ではないので、2章の`if`には入らない。

```sh
# docker-entrypoint.sh:145-148
um="$(umask)"
if [ "$um" = '0022' ]; then
  umask 0077
fi
```

17. umaskが既定の`0022`なら`0077`にする。\
    この後Redisが作るファイルは、所有者だけが読み書きできる（`-rw-------`）。\
    `/proc/1/status`の`Umask`は`0077`。`docker exec`で入ったシェルはこのスクリプトを通らないので、`0022`のまま。

```sh
# docker-entrypoint.sh:150-152・157・179
if [ "$IS_REDIS_SERVER" ] \
    && ! [ "$IS_REDIS_SENTINEL" ]; then
  echo "Starting Redis Server"
  modules_dir="/usr/local/lib/redis/modules/"
  ...
  for module in "$modules_dir"/*.so;
  ...
    set -- "$@" --loadmodule "$module"
```

（モジュールのファイルを確かめる部分は省略）

18. `Starting Redis Server`を出す（ログの最初の行）。
19. `/usr/local/lib/redis/modules/`の`.so`を1つずつ確かめ（中身がある・フォルダではない・読める・実行できる）、`--loadmodule <ファイル>`を引数の後ろに足す。\
    `modules_dir`の末尾の`/`に`/*.so`をつなげるので、パスに`//`が入る（ログの`modules//redisbloom.so`）。
20. 入っているモジュールは4つ：`redisbloom.so`（0.6MB）・`redisearch.so`（20MB）・`redistimeseries.so`（3.5MB）・`rejson.so`（45MB）。\
    このアプリは使わないが、このイメージでは止める設定がない（止めるには`entrypoint:`で`redis-server`を直接起動する）。
21. 最後の`exec "$@"`で、`redis-server`に置き換わる。最終的な引数は次のとおり。

```text
redis-server --appendonly yes --maxmemory 128mb
  --maxmemory-policy allkeys-lru
  --loadmodule /usr/local/lib/redis/modules//redisbloom.so
  --loadmodule .../redisearch.so
  --loadmodule .../redistimeseries.so
  --loadmodule .../rejson.so
```

（`ps`では、Redisが書き換えた`redis-server *:6379`という名前で表示される）

## 4. redis-serverの起動

ログの形は`<PID>:<役割> <時刻> <種類> <メッセージ>`。

22. 役割は、初期化の途中までは`C`、初期化の後は`M`（master）。\
    種類は`*`がふつうのお知らせ、`#`が警告。

```text
1:C 21:30:58.097 # WARNING Memory overcommit must be
  enabled! ...
1:C 21:30:58.099 * Redis version=8.10.3, bits=64,
  commit=00000000, modified=1, pid=1, just started
1:C 21:30:58.099 * Configuration loaded
1:M 21:30:58.100 * Increased maximum number of open
  files to 10032 (it was originally set to 1024).
1:M 21:30:58.102 * Running mode=standalone, port=6379.
```

（日付を省き、長い行を折り返している）

23. `Memory overcommit must be enabled!`：WSLのカーネルの`vm.overcommit_memory`が`0`だという警告。\
    Redisは、ファイルへの書き出し（RDBの保存とAOFの書き直し。5章）を、forkした子プロセスで行う。\
    `0`だと、メモリが少ないときにforkが失敗することがある。\
    この値はコンテナごとに変えられず、WSL側で`sysctl vm.overcommit_memory=1`にするしかない。
24. `Configuration loaded`：設定ファイルはなく、コマンドラインの引数だけを読んだ。
25. `Increased maximum number of open files to 10032`：同時に開けるファイルの数を、接続数の上限（`maxclients`の10000）と予備の32に合わせて上げた。\
    capabilitiesはすべて落としているが、ハードの上限（1048576）より下なので上げられる。\
    Redisはソフトとハードの両方を10032にする（`/proc/1/limits`の`Max open files 10032 10032`）。
26. モジュールが読み込まれる（ログは50行ほどあるので省略）。\
    RediSearchは、検索用のスレッドを8つ作る（`search-workers default: 8`）。

### データを戻す

既存のボリューム（今回）：

```text
1:M 21:30:58.165 * Server initialized
1:M 21:30:58.166 * Reading RDB base file on AOF
  loading...
1:M 21:30:58.168 * Loading RDB produced by version
  8.10.3
1:M 21:30:58.168 * RDB age 480230 seconds
1:M 21:30:58.168 * RDB is base AOF
1:M 21:30:58.168 * Done loading RDB, keys loaded: 0,
  keys expired: 0.
1:M 21:30:58.169 * DB loaded from base file
  appendonly.aof.1.base.rdb: 0.003 seconds
1:M 21:30:58.169 * DB loaded from incr file
  appendonly.aof.1.incr.aof: 0.001 seconds
1:M 21:30:58.193 * Opening AOF incr file
  appendonly.aof.1.incr.aof on server start
1:M 21:30:58.193 * Ready to accept connections tcp
```

27. `--appendonly yes`なので、AOFからデータを戻す。\
    AOFは`/data/appendonlydir/`の3つのファイルでできていて、manifestに読む順が書いてある。

```text
file appendonly.aof.1.base.rdb seq 1 type b
file appendonly.aof.1.incr.aof seq 1 type i startoffset 0
```

（`appendonly.aof.manifest`）

28. base（`type b`）：ある時点の全データ。`aof-use-rdb-preamble yes`なので、RDB形式で書かれている（`Reading RDB base file`）。\
    今回のbaseは11-21に作られたもの（`RDB age 480230 seconds`は約5.6日）で、キーは0個だった。
29. incr（`type i`）：baseの後に実行された書き込みのコマンドを、そのまま追記したもの。順に実行し直して、データを戻す。\
    今回のincrに入っていたコマンドを数えると、次のとおり。

```text
     31 SET      （すべてPXAT付き）
     13 DEL
      7 MULTI
      7 PEXPIREAT
      7 EXEC
      4 SELECT
```

30. セッションは、アプリが`SET session:<ID> <中身> EX 43200`（12時間）で書く（`docs/6H.md`の4章）。\
    AOFには、相対時間の`EX`ではなく、期限の時刻（ミリ秒）を書いた`PXAT`で記録される。\
    そのため、戻したときも元の期限のままで、期限を過ぎたキーは消える。今回は全部が期限切れで、戻した後のキーは0個（`DBSIZE`が0）。
31. `MULTI`〜`EXEC`は、回数制限（Flask-Limiter）がLuaスクリプトで実行した`incrby`と`expire`を、Redisが実行結果として記録したもの。\
    `expire`も、期限の時刻を書いた`PEXPIREAT`に変えて記録される。

```text
MULTI
incrby
  LIMITS:LIMITER/172.18.0.1/accounts.signup/5/1/minute 1
PEXPIREAT
  LIMITS:LIMITER/172.18.0.1/accounts.signup/5/1/minute
  1795248636939
EXEC
```

（AOFのプロトコルの記号を省き、1つのコマンドを1行にしている。キーの`172.18.0.1`については`docs/6H.md`の1章）

32. `Opening AOF incr file ... on server start`：この後の書き込みは、同じincrファイルの続きに追記する。

新しいボリューム（別のプロジェクト名で試した）：

```text
1:M 21:33:55.521 * Server initialized
1:M 21:33:55.522 * BGSAVE done, 0 keys saved,
  0 keys skipped, 89 bytes written.
1:M 21:33:55.534 * Creating AOF base file
  appendonly.aof.1.base.rdb on server start
1:M 21:33:55.552 * Creating AOF incr file
  appendonly.aof.1.incr.aof on server start
1:M 21:33:55.552 * Ready to accept connections tcp
```

33. AOFがないので、空のデータをRDB形式で書いてbaseにし（89バイト）、空のincrとmanifestを作る。

### 接続を受け付ける

```text
1:M 21:30:58.193 * Ready to accept connections tcp
1:M 21:30:58.193 # WARNING: Redis does not require
  authentication and is not protected by network
  restrictions. Redis will accept connections from any
  IP address on any network interface.
```

34. `Ready to accept connections tcp`：6379番で接続を受け付け始める。\
    `bind`は`* -::*`（すべてのIPv4のアドレスと、使えればすべてのIPv6のアドレス。`-`は「使えなくてもエラーにしない」の印）。
35. 警告は、パスワードがなく、protected modeも切れていて、すべてのアドレスで待っているときに出る。\
    protected modeが有効だと、パスワードがないときはループバック以外からの接続を断るので、webから接続できない。\
    公式イメージは、そのためにprotected modeの既定値を`no`にしてある（`CONFIG GET protected-mode`は`no`）。
36. 実際に届くのは、次の2つだけ。
    - 同じネットワーク（`fl-demonstro_default`）のコンテナ（web）
    - WSL自身（ブリッジ経由。`docs/6C.md`の7）。WSLから172.18.0.2:6379に`PING`を送ると、パスワードなしで`+PONG`が返った。

    `ports`を書いていないので、ほかのマシンからは届かない。\
    もっと固めるなら、`--requirepass`でパスワードを付け、`REDIS_URL`を`redis://:パスワード@redis:6379/0`にする。

## 5. 動いている間の設定

`redis-cli CONFIG GET`で確かめた、主な値：

```text
save                         3600 1 300 100 60 10000
appendfsync                  everysec
aof-use-rdb-preamble         yes
auto-aof-rewrite-percentage  100
auto-aof-rewrite-min-size    67108864
maxclients                   10000
protected-mode               no
bind                         * -::*
```

37. 書き込みのコマンドは、AOFのincrファイルに追記される。\
    `appendfsync everysec`なので、ディスクへの書き込みを確定させる`fsync`は1秒に1回。\
    Redisのプロセスだけが落ちたときはほとんど失わないが、マシンごと落ちると、最大で1秒ほどの書き込みを失う。
38. `save`は、設定ファイルがないときの既定値で、「3600秒で1回以上」「300秒で100回以上」「60秒で10000回以上」の変更があると、RDBのスナップショット（`/data/dump.rdb`）をforkした子プロセスで書く。\
    AOFと同時に動いていて、止めるときにも書く（`docs/6I.md`の2章）。\
    ただし、`--appendonly yes`のときの起動ではAOFだけを読み、`dump.rdb`は読まない。
39. AOFの書き直し：incrがbaseの大きさの100%以上増え、かつ64MB以上になると、forkした子プロセスで今のデータを新しいbaseに書き、新しいincr（`seq 2`）に切り替える。\
    今のincrは10KBほどなので、まだ一度も書き直されていない（baseが11-21のままなのはこのため）。
40. `maxmemory 128mb`・`allkeys-lru`：使うメモリが128MBを超えそうになると、すべてのキーの中から、しばらく使われていないものを消す（すべてのキーを調べるのではなく、5つずつ選んで比べる近似）。\
    セッションが消えるとログアウトした状態になり（「ログインしたままにする」のCookieがあれば戻る）、回数制限のキーが消えると、その回数は0からになる。

## 6. ファイルと権限のまとめ

```text
/data/                       redis:redis  drwxr-xr-x
  dump.rdb                   redis:redis  -rw-------
  appendonlydir/             redis:redis  drwx------
    appendonly.aof.1.base.rdb             -rw-------
    appendonly.aof.1.incr.aof             -rw-------
    appendonly.aof.manifest               -rw-------
```

41. `/data`自体はイメージからコピーされた所有者と権限（`drwxr-xr-x`）のまま。中のファイルは、umask（17）で所有者だけのものになっている。
42. ほかのコンテナ（`alpine`など）から同じボリュームを見ると、redisユーザーがいないので、uidとgidの数字（999と1000）で表示される。
