# テンプレートの仕組み（02）

コードの抜粋は、iPhone の縦画面で読めるよう、元のファイルから改行やインデントを変えている（中身は同じ）。

## 全体像

`src/fl_demonstro/templates/` の中身：

- `base.html`\
  全ページの土台。\
  partials/ の部品を組み立て、各ページの中身を content ブロックに入れる。
- `partials/`：base.html が include する部品
  - `navbar.html`：ナビゲーションバー
  - `flash.html`：flash メッセージ
  - `footer.html`：フッター
- `macros/`
  - `forms.html`：フォーム表示のマクロ（各ページが import する）
- `main/`
  - `index.html`：トップページ
- `accounts/`
  - `login.html`：ログイン
  - `signup.html`：サインアップ
  - `signup_done.html`：登録完了
- `errors/`
  - `error.html`：エラー画面（404 など）

1ページは次のように組み立てられる。

```
base.html
├─ <head>
│   └─ title ブロック
├─ partials/navbar.html
├─ <main>
│   ├─ partials/flash.html
│   └─ content ブロック
├─ partials/footer.html
└─ Bootstrap の JS
```

title ブロックと content ブロックは、各ページが上書きする。

テンプレート同士をつなぐ仕組みは3つあり、役割で使い分けている。

- **extends**
  - 書き方：`{% extends "base.html" %}` と `{% block %}`
  - 使っている場所：各ページ → `base.html`
  - 呼び出し元の変数：見える（同じ描画の一部）
- **include**
  - 書き方：`{% include "partials/navbar.html" %}`
  - 使っている場所：`base.html` → `partials/`
  - 呼び出し元の変数：見える
- **import**
  - 書き方：`{% from "macros/forms.html" import render_field %}`
  - 使っている場所：`login.html`・`signup.html` → `macros/`
  - 呼び出し元の変数：見えない（引数で渡す）

### `.venv/.../flask/templating.py:102-108`

```python
def _iter_loaders(
    self, template: str
) -> t.Iterator[
    tuple[Scaffold, BaseLoader]
]:
    loader = self.app.jinja_loader
    if loader is not None:
        yield self.app, loader

    for blueprint in (
        self.app.iter_blueprints()
    ):
        loader = blueprint.jinja_loader
```

- Flask のローダー（`DispatchingJinjaLoader`）は、アプリの `templates/` → 各ブループリントの置き場の順に探す。\
  このプロジェクトではブループリント側が `None` なので、アプリの `templates/` だけを見る。
- `extends`・`include`・`import` に書く名前も、書いたファイルからの相対パスではなく `templates/` からのパス。\
  `base.html` の中でも `accounts/login.html` の中でも、`"partials/navbar.html"`・`"macros/forms.html"` と書く。

## 2. `render_template()` の流れ

### `.venv/.../flask/templating.py:139-151`（docstring と `# type: ignore` は省略）

```python
def render_template(
    template_name_or_list: str
    | Template
    | list[str | Template],
    **context: t.Any,
) -> str:
    app = (
      current_app._get_current_object()
    )
    template = (
        app.jinja_env
        .get_or_select_template(
            template_name_or_list
        )
    )
    return _render(
        app, template, context
    )
```

### `.venv/.../flask/templating.py:127-136`

```python
def _render(
    app: Flask,
    template: Template,
    context: dict[str, t.Any],
) -> str:
    app.update_template_context(context)
    before_render_template.send(
        app,
        _async_wrapper=app.ensure_sync,
        template=template,
        context=context,
    )
    rv = template.render(context)
    template_rendered.send(
        app,
        _async_wrapper=app.ensure_sync,
        template=template,
        context=context,
    )
    return rv
```

1. `get_or_select_template()`：名前からテンプレートを探し、Python のコードにコンパイルする。\
   結果は Jinja の環境にキャッシュされ、2回目以降は使い回す。
2. `update_template_context()`：ビューが渡した変数に、コンテキストプロセッサの変数を足す（3章）。
3. `template.render()`：HTML の文字列を作る。\
   ビューはこれをそのまま、またはステータスコードと組にして返す。

キャッシュとファイルの変更：

- `TEMPLATES_AUTO_RELOAD` は未設定（`None`）で、そのときは `app.debug` に従う。
- `FLASK_DEBUG=1` の開発時は、テンプレートを使うたびにファイルの更新を確認して読み直す。\
  保存してブラウザを再読み込みすれば反映される。
- 本番（gunicorn、デバッグなし）は最初に読み込んだものを使い続ける。\
  テンプレートを変えたら再起動（Docker ではイメージの作り直し）が必要。

def _render_error(
    e: HTTPException,
    title: str,
    message: str,
) -> Response:
    # e.get_response() を元にすると、
    # 405 の Allow ヘッダーなどが

## 3. テンプレートの中で使える変数

ビューが渡していない `url_for` や `current_user` が使えるのは、Flask と拡張機能が Jinja のグローバル変数・コンテキストプロセッサとして登録しているため。

- `url_for()`
  - 登録元：Flask（グローバル変数）
  - 使っている場所：ほぼ全テンプレート（リンク・フォームの送信先）
- `get_flashed_messages()`
  - 登録元：Flask（グローバル変数）
  - 使っている場所：`partials/flash.html`
- `request`
  - 登録元：Flask（グローバル変数＋コンテキストプロセッサ）
  - 使っている場所：`partials/navbar.html`（`request.endpoint`）、`accounts/login.html`（`request.args`）
- `session`・`g`・`config`
  - 登録元：Flask（グローバル変数）
  - 使っている場所：なし
- `csrf_token()`
  - 登録元：Flask-WTF（グローバル変数＋コンテキストプロセッサ）
  - 使っている場所：`partials/navbar.html`（ログアウトのフォーム）
- `current_user`
  - 登録元：Flask-Login（コンテキストプロセッサのみ）
  - 使っている場所：`partials/navbar.html`・`main/index.html`
- `form`・`title`・`message`
  - 登録元：ビューの `render_template()` の引数
  - 使っている場所：各ページ

グローバル変数は、どのテンプレートからも見える（import したマクロの中からも）。

コンテキストプロセッサの変数とビューが渡した変数は「その描画の変数」で、include には引き継がれるが、import には引き継がれない（6章）。

描画の順番：

1. `render_template("main/index.html")` で子テンプレートの描画が始まる。
2. 先頭の `{% extends "base.html" %}` により、出力の枠は `base.html` になる。\
   子のブロックの外にある `{% from ... import %}` や `{% set %}` は実行されるが、ブロックの外の文字や HTML は出力されない。
3. `base.html` を上から描画し、`{% block title %}`・`{% block content %}` の位置に子の同名ブロックの中身を入れる。\
   子が定義していないブロックは、`base.html` に書いた既定の中身（ここでは空）になる。

小さなテンプレートで確かめた結果（実際は1行で書いたものを、見やすいように改行している）：

```

[base 前]
{% block content %}
base の既定
{% endblock %}
[base 後]

page.html:
{% extends 'base.html' %}
ブロックの外の文字
{% block content %}
page の中身
{% endblock %}

page.html の描画結果:
[base 前]page の中身[base 後]
```

- `errors/error.html` は `{% block title %}{{ title }}{% endblock %}` のように、ビューから渡された変数をブロックの中で使っている。

## 5. include：partials/ の部品を差し込む

`{% include %}` は、その位置に別のテンプレートの描画結果を入れる。

- 呼び出し元の変数を引き継ぐ。\
  `navbar.html` で `current_user` が使えるのはこのため。
- 部品の中の `{% set %}` は呼び出し元に漏れない。\
  `flash.html` の `alert_colors` は `flash.html` の中だけの変数。
- 部品の中に block を書いても、各ページから上書きできない。\
  次のように、部品に書いた既定の中身が出てページの中身は消える。\
  `<main>` と content ブロックを `base.html` に置いているのはこのため。

確かめた結果（実際は1行で書いたものを、見やすいように改行している）：

```
_main.html:
<main>
{% block content %}
（部品の中の既定の中身）
{% endblock %}
</main>

base.html:
<body>
{% include '_main.html' %}
</body>

page.html:
{% extends 'base.html' %}
{% block content %}
ページの中身
{% endblock %}

page.html の描画結果:
<body><main>
（部品の中の既定の中身）
</main></body>
```

## 6. import：macros/forms.html のマクロを使う

### `src/fl_demonstro/templates/accounts/login.html`

```html
{% extends "base.html" %}
{% from "macros/forms.html" import
   render_checkbox,
   render_field,
   render_form_errors %}

{% block title %}ログイン{% endblock %}

{% block content %}
<div class="row justify-content-center">
<div class="col-md-6 col-lg-5">
  <h1 class="h3 mb-4">ログイン</h1>
  {{ render_form_errors(form) }}
  {# ログイン後に元のページへ
     戻れるよう、?next=... を
     引き継ぐ #}
  <form
    method="post"
    action="{{ url_for(
      'accounts.login',
      next=request.args.get('next')
    ) }}"
    novalidate
  >
    {{ form.hidden_tag() }}
    {{ render_field(form.username) }}
    {{ render_field(form.password) }}
    {{ render_checkbox(form.remember) }}
    {{ form.submit(
      class_="btn btn-primary w-100"
    ) }}
  </form>
  <p class="mt-3 text-center">
    アカウントをお持ちでない方は
    <a href="{{
      url_for('accounts.signup')
    }}">サインアップ</a>
  </p>
</div>
</div>
{% endblock %}
```

- 2行目の import はブロックの外にあるが、4章のとおり実行されるので、ブロックの中でマクロを使える。
- `form.hidden_tag()` は、隠しフィールド（Flask-WTF の CSRF トークンを含む）をまとめて出力する。\
  このときトークンがセッションに入るので、ログイン画面を開くだけでセッションが作られる（`docs/01.md` の6章）。
- `form.submit(class_=...)` のように、WTForms のフィールドは呼び出すと HTML になる。\
  `class` は Python の予約語なので `class_` と書く。
- `url_for()` は値が `None` の引数を URL に含めない。\
  `?next=` がないときの送信先は `/accounts/login` になる。
- `novalidate` でブラウザの入力チェックを止め、エラーはサーバー側の WTForms のチェック結果で表示する。

### `src/fl_demonstro/templates/macros/forms.html:6-24`

```html
{% macro render_field(field) %}
  {% set help_id =
     field.id ~ "-help" %}
  {% set error_id =
     field.id ~ "-error" %}
  <div class="mb-3">
    {{ field.label(
      class_="form-label"
    ) }}
    {{ field(
      class_="form-control"
        ~ (" is-invalid"
           if field.errors else ""),
      aria_describedby=(
        error_id if field.errors
        else (
          help_id if field.description
          else false
        )
      ),
      **kwargs
    ) }}
    {% if field.errors %}
      <div
        id="{{ error_id }}"
        class="invalid-feedback"
      >
        {% for error in field.errors %}
          {{ error }}
          {% if not loop.last %}
            <br>
          {% endif %}
        {% endfor %}
      </div>
    {% elif field.description %}
      <div
        id="{{ help_id }}"
        class="form-text"
      >
        {{ field.description }}
      </div>
    {% endif %}
  </div>
{% endmacro %}
```

- `field.label()` は `<label for="...">`、`field(...)` は `<input ...>` を出力する。
- エラーがあれば `is-invalid` を付け、入力欄の下に `invalid-feedback`（赤字）でエラーを出す。
- `aria-describedby` で、入力欄とエラー文・説明文を結び付ける（スクリーンリーダーが読み上げる）。\
  値が `false` のとき、WTForms は属性ごと出力しない。
- `**kwargs`：マクロの中で `kwargs` を使うと、定義していないキーワード引数がそこに集まる。\
  `render_field(form.username, placeholder="...")` のような追加の属性を入力欄まで渡せる。
- `render_checkbox`（26-32行）はチェックボックス用、`render_form_errors`（34-39行）は特定の項目に属さないエラー（ログイン失敗など）を表示する。

### import は呼び出し元の変数を引き継がない

`{% from ... import %}` はマクロの定義ファイルを、呼び出し元の変数なしで読み込む。

マクロの中で何が見えるかを確かめた結果：

- `url_for`・`request`・`csrf_token`（グローバル変数）
  - `import`（既定）：見える
  - `import ... with context`：見える
- `current_user`（コンテキストプロセッサ）
  - `import`（既定）：見えない
  - `import ... with context`：見える

`forms.html` のマクロは引数（`field`・`form`）しか使っていないので、既定の import で動く。

マクロの中で `current_user` などを使いたくなったら、引数で渡す。

引数なら、マクロが何に頼っているかが呼び出し側から分かる。

## 7. 自動エスケープと CSP

### 自動エスケープ

- Flask は `.html` のテンプレートで自動エスケープを有効にしている。\
  `{{ ... }}` で出力する値の `<`・`>`・`&`・`"` は HTML の文字参照に変わる。
- 確かめた結果：`flash("<b>太字?</b>", "success")` は `&lt;b&gt;太字?&lt;/b&gt;` として出力され、タグとして働かない。\
  ユーザー名やエラー文に HTML が含まれても XSS にならない。
- WTForms のフィールドや `form.hidden_tag()` が返すのは `Markup`（エスケープ済みの印が付いた文字列）。\
  そのため二重にエスケープされず、そのまま HTML として出る。
- 利用者の入力に `|safe` を付けると、このエスケープが効かなくなる。

### `src/fl_demonstro/security.py:20-32`（抜粋）

```python
inline = (
    " 'unsafe-inline'"
    if allow_inline
    else ""
)
return "; ".join(
    [
        "default-src 'self'",
        "script-src 'self' "
        f"{BOOTSTRAP_CDN}{inline}",
        "style-src 'self' "
        f"{BOOTSTRAP_CDN}{inline}",
        # Bootstrap のアイコンが
        # data: 形式の画像を使う
        "img-src 'self' data:",
        ...
    ]
)
```

- CSP により、スクリプトとスタイルは自分のサイトと Bootstrap の置き場所（`https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/`）からしか読み込めない。
- そのため、テンプレートに `<script>...</script>`・`onclick="..."`・`style="..."` を直接書いても、ブラウザが実行・適用しない。\
  見た目は Bootstrap のクラスで付ける。
- `base.html` の Bootstrap のバージョンを変えたら、`security.py` の `BOOTSTRAP_CDN` も変える。\
  忘れると `tests/test_security.py` の `test_external_files_in_page_are_allowed_by_csp` が失敗する。
- 開発用のデバッグツールバーを使うときだけ、`CSP_ALLOW_INLINE` で `'unsafe-inline'` を許している（`__init__.py` の `_init_debug_toolbar()`）。

## 8. 1リクエストの流れ（未ログインで `GET /accounts/login`）

1. ルーティングで `accounts.login` ビューが選ばれる。\
   回数制限は POST だけなので数えない。
2. ビューが `LoginForm()` を作り、`render_template("accounts/login.html", form=form)` を呼ぶ。
3. コンテキストプロセッサが `request`・`current_user`（未ログインなので匿名ユーザー）・`csrf_token` などを足す。
4. `login.html` は `extends "base.html"` なので、`base.html` を枠にして描画が進む。\
   先に `macros/forms.html` の import が実行される。
5. `<title>` には title ブロックの「ログイン」が入り、「ログイン | fl-demonstro」になる。
6. `partials/navbar.html`：未ログインなので、ログインとサインアップのリンクを出す。\
   `request.endpoint == 'accounts.login'` なので、ログインに `active` を付ける。
7. `partials/flash.html`：`_flashes` がないので何も出さない。
8. content ブロック：`render_form_errors`（エラーなし）、`form.hidden_tag()`（CSRF トークンを発行してセッションに保存）、`render_field` で入力欄を出す。
9. `partials/footer.html` と Bootstrap の JS を出して、HTML ができる。
10. `after_request` で CSP などのセキュリティ用ヘッダーが付く。\
    セッション（CSRF トークン入り）が保存されて、ブラウザに返る。
