# 全体の構成（03）

## 全体像

Flask のアカウント機能（サインアップ・ログイン・ログアウト）を持つ Web アプリ。アプリケーションファクトリ（`create_app()`）とブループリントで組み立て、データは SQLite、セッションはサーバー側（Redis またはファイル）に保存する。本番は Docker で gunicorn と Redis を動かす。

```
fl-demonstro/
├── src/fl_demonstro/        … アプリ本体（Python パッケージ）
├── tests/                   … 自動テスト（pytest）
├── migrations/              … データベースの形の変更履歴（Alembic）
├── docs/                    … 解説（この文書など）
├── docker/entrypoint.sh     … コンテナ起動時の処理
├── Dockerfile               … 本番用イメージの作り方
├── compose.yaml             … Docker で web と Redis を動かす設定
├── .github/ci.yml           … CI（GitHub Actions）の設定
├── pyproject.toml           … 依存パッケージとツール（ruff・mypy・pytest・djlint）の設定
├── uv.lock                  … 依存パッケージのバージョンの固定
├── .python-version          … Python のバージョン（3.15）
├── .pre-commit-config.yaml  … コミット・プッシュ前の自動チェック
├── .env.example             … 環境変数のひな形（.env にコピーして使う）
└── instance/                … SQLite とセッションのファイル（Git の対象外）
```

| 層 | ファイル | 内容 |

## 2. `create_app()`：アプリの組み立て

### `src/fl_demonstro/__init__.py:81-117`

```python
def create_app(config_class: type[Config] | None = None) -> Flask:
    """アプリケーションファクトリ：Flask アプリを作って返す。

    config_class を省略すると、環境変数 APP_ENV に合った設定を使う。
    """
    app = Flask(__name__, instance_path=_instance_path())
    app.config.from_object(config_class or get_config())

    if not app.config.get("SECRET_KEY"):
        raise RuntimeError(
            "SECRET_KEY が設定されていません。.env に SECRET_KEY=... を書いてください。"
        )

    _trust_reverse_proxy(app)

    # 拡張機能をアプリと結びつける
    db.init_app(app)
    migrate.init_app(app, db)
    csrf.init_app(app)
    limiter.init_app(app)
    login_manager.init_app(app)
    _configure_session_storage(app)
    server_session.init_app(app)
    _init_debug_toolbar(app)

    init_security(app)
    init_error_handlers(app)

    # ブループリントの登録
    # （accounts を読み込むとモデルも読み込まれ、Flask-Migrate がテーブルを見つけられる）
    from fl_demonstro.accounts import bp as accounts_bp
    from fl_demonstro.main import bp as main_bp

    app.register_blueprint(main_bp)
    app.register_blueprint(accounts_bp)

    return app
```

1. `instance_path`：SQLite やセッションのファイルを置く場所。環境変数 `INSTANCE_PATH`（Docker では `/app/instance`）、なければプロジェクト直下の `instance/`。
2. 設定：引数で設定クラスを渡されなければ、`APP_ENV` から選ぶ（3章）。`SECRET_KEY` がなければ起動を止める。
3. `_trust_reverse_proxy()`：`TRUSTED_PROXY_COUNT` が1以上なら `ProxyFix` を挟み、`X-Forwarded-For` などから本当の接続元を読む。
4. 拡張機能の `init_app()`：`extensions.py` で作っておいたオブジェクトを、このアプリに結び付ける。セッションの保存先は `server_session.init_app()` の前に決める（`docs/01.md` の2章）。
5. `init_security()`・`init_error_handlers()`：全レスポンスへのヘッダーと、エラー画面のハンドラを登録する。
6. ブループリントの登録：ブループリントは `create_app()` の中で import し、アプリに登録する。`accounts` を読み込むと `views.py` 経由で `models.py` も読み込まれ、`User` モデルが `db` に登録されるので、Flask-Migrate がテーブルを見つけられる。

アプリケーションファクトリにしている理由：

- テストで、設定を変えたアプリを何個でも作れる（`create_app(TestingConfig)`）。
- 拡張機能をモジュールの変数として持つので、ビューやモデルから `from fl_demonstro.extensions import db` で使える。

アプリを起動する入口は2つある。

| 入口 | 使う場面 | `create_app()` の見つけ方 | `.env` |
| --- | --- | --- | --- |
| `flask` コマンド（`flask run`・`flask db upgrade`） | 開発、マイグレーション | `FLASK_APP=fl_demonstro` から `create_app` を自動で探す | python-dotenv が読み込む |
| gunicorn | Docker（本番） | `fl_demonstro:create_app()` を直接呼ぶ | 読まない（compose.yaml の `environment` で渡す） |

## 3. 設定（`config.py`）

| クラス | 選び方 | 主な違い |
| --- | --- | --- |
| `Config` | （共通の親） | 環境変数から `SECRET_KEY`・`DATABASE_URL`・`REDIS_URL` などを読む。Cookie は HTTPS のみ |
| `DevelopmentConfig` | `APP_ENV=development` | Cookie を http でも送る。デバッグツールバーでリダイレクトを止めない |
| `ProductionConfig` | `APP_ENV=production`（未設定のときも） | Cookie は HTTPS のみ（`SESSION_COOKIE_SECURE=false` で緩められる） |
| `TestingConfig` | `APP_ENV` では選べない。テストが直接渡す | CSRF・回数制限を切る。DB とセッションはメモリ。Argon2 を最小の強さに |

- `APP_ENV` が未設定なら本番用になる。設定し忘れたときに、安全側（Cookie は HTTPS のみ、デバッグなし）に倒れる。
- `TestingConfig` は CSRF 対策を切っているので、`APP_ENV` で選べないようにして、本番で使われる道を塞いでいる。

### 環境変数

| 名前 | 内容 | 未設定のとき |
| --- | --- | --- |
| `SECRET_KEY` | セッション・CSRF トークンの署名の鍵 | 起動しない |
| `APP_ENV` | 設定クラスの選択 | `production` |
| `FLASK_APP`・`FLASK_DEBUG` | `flask` コマンドの対象とデバッグモード | — |
| `DATABASE_URL` | データベースの場所 | `sqlite:///app.db`（`instance/app.db`） |
| `REDIS_URL` | セッションと回数制限の保存先 | セッションは `instance/sessions/`、回数制限はメモリ |
| `RATELIMIT_STORAGE_URI` | 回数制限だけ別の保存先にする | `REDIS_URL` |
| `INSTANCE_PATH` | instance フォルダの場所 | プロジェクト直下の `instance/` |
| `SESSION_COOKIE_SECURE` | 本番用で http のまま試すときに `false` | `true` |
| `TRUSTED_PROXY_COUNT` | 前に置いたリバースプロキシの数 | `0`（ヘッダーを信用しない） |

## 4. 拡張機能（`extensions.py`）

| オブジェクト | 拡張機能 | 役割 |
| --- | --- | --- |
| `db` | Flask-SQLAlchemy | データベース（モデルの定義と操作）。制約名の付け方（`NAMING_CONVENTION`）を決めて、マイグレーションを安定させる |
| `migrate` | Flask-Migrate | テーブルの形の変更（Alembic）を `flask db` コマンドで扱う |
| `csrf` | Flask-WTF | POST などに CSRF トークンがなければ 400 にする |
| `limiter` | Flask-Limiter | 送信回数の制限（既定の識別子は IP アドレス） |
| `server_session` | Flask-Session | セッションの中身をサーバー側に置く（Cookie にはセッション ID だけ） |
| `login_manager` | Flask-Login | ログイン状態の管理。ログインが必要なページで `accounts.login` に飛ばす |

拡張機能ではないが、パスワードのハッシュ化に argon2-cffi、開発時のみ Flask-DebugToolbar を使う。

## 5. URL の一覧

| URL | メソッド | エンドポイント | 内容 | 制約 |
| --- | --- | --- | --- | --- |
| `/` | GET | `main.index` | トップページ | — |
| `/accounts/signup` | GET・POST | `accounts.signup` | サインアップ | POST は1分5回・1時間20回まで |
| `/accounts/signup/done` | GET | `accounts.signup_done` | 登録完了 | — |
| `/accounts/login` | GET・POST | `accounts.login` | ログイン | 失敗は IP ごとに1分5回・1時間20回、ユーザー名ごとに1時間10回まで |
| `/accounts/logout` | POST | `accounts.logout` | ログアウト | `@login_required` |
| `/static/<path>` | GET | `static` | 静的ファイル（Flask が自動で作る。今はファイルなし） | — |

- `accounts` は `url_prefix="/accounts"` なので、ビューに書いた `/login` が `/accounts/login` になる。
- エンドポイント名は `ブループリント名.関数名`。`url_for('accounts.login')` やテンプレートの `request.endpoint` で使う。

## 6. `accounts/` の中身

| ファイル | 主なもの | 内容 |
| --- | --- | --- |
| `models.py` | `User`・`load_user()` | `users` テーブル（`id`・`username`・`password_hash`・`created_at`）。ユーザー名は小文字だけで保存する（`@validates` で確認）。`authenticate()` はユーザーがいないときもダミーの照合をして、応答時間からユーザー名の有無を推測させない。正しいパスワードで古い方式のハッシュなら保存し直す |
| `forms.py` | `SignupForm`・`LoginForm` | 入力チェック。ユーザー名は `^[a-z0-9]{3,32}$`、重複は `validate_username()`、パスワードは `validate_password()` でポリシーを確認 |
| `passwords.py` | `hash_password()`・`verify_password()`・`password_policy_error()` など | Argon2id でハッシュ化。以前の scrypt のハッシュも照合できる。ポリシーは 8〜128文字、よく使われるパスワード・ユーザー名を含むもの・同じ文字の繰り返し・連続した文字を弾く |
| `views.py` | `signup`・`signup_done`・`login`・`logout` | 画面の処理。ログイン状態が変わるときにセッション ID を作り直す（`docs/01.md` の4章）。回数制限のデコレータ |
| `data/common_passwords.txt.gz` | — | よく使われるパスワード 46,483 件（SecLists の NCSC 上位10万件を加工） |

## 7. 1リクエストの流れ

本番（Docker）で `POST /accounts/login` が来た場合。

1. gunicorn のワーカーがリクエストを受け、WSGI で Flask に渡す（`TRUSTED_PROXY_COUNT` が1以上なら、先に `ProxyFix` が接続元を書き換える）。
2. リクエストコンテキストの開始：URL を照合してエンドポイントを決め、Flask-Session が Cookie のセッション ID で Redis からセッションを読む。
3. `before_request`（登録順）：
   1. Flask-WTF：CSRF トークンを確認する。なければ 400（`errors/error.html`）。
   2. Flask-Limiter：回数制限を確認する。超えていれば 429。
4. ビュー `login()`：`LoginForm` で入力を確認し、`User.authenticate()` で照合する。成功ならセッションを作り直してリダイレクト、失敗ならフォームを 400 で再表示する（`render_template()` は `docs/02.md`）。`current_user` は最初に使われたとき、`load_user()` でデータベースから読み込まれる。
5. 例外が起きたら：`errors.py` のハンドラが `errors/error.html` を描画する。500 のときはデータベースの操作を取り消してから出す。
6. `after_request`（登録と逆の順）：
   1. `security.py`：CSP などのセキュリティ用ヘッダーを付ける。ログイン中は `Cache-Control: no-store`。
   2. Flask-Login：「ログインしたままにする」の Cookie を付ける・消す。
   3. Flask-Limiter：ログインに失敗していれば（302 以外）回数を数える。
7. Flask-Session がセッションを Redis に保存し、Cookie を付けてレスポンスを返す（`docs/01.md` の3章）。

## 8. データベースとマイグレーション

- データベースは SQLite。`sqlite:///app.db` のような相対パスは、Flask-SQLAlchemy が instance フォルダからのパスとして扱うので、`instance/app.db` になる。
- テーブルの形の変更は Flask-Migrate（Alembic）で管理し、`migrations/versions/` に履歴が並ぶ。

| リビジョン | 内容 | 前のリビジョン |
| --- | --- | --- |
| `d96ac129be18` | `users` テーブルを作る | — |
| `e7469dcb534f` | ユーザー名を大文字・小文字を区別せずに一意にする | `d96ac129be18` |
| `85dd7755e1ac` | ユーザー名を小文字だけで保存する | `e7469dcb534f` |

- Docker では、コンテナを起動するたびに `docker/entrypoint.sh` が `flask db upgrade` を実行してから gunicorn を起動する。
- テストの多くは `db.create_all()` でモデルから直接テーブルを作る。マイグレーションそのものは `tests/test_migrations.py` が実際に流して確かめる。

## 9. 実行環境

| | 開発（ローカル） | Docker（本番相当） |
| --- | --- | --- |
| 起動 | `flask run`（ポート 5000） | gunicorn・ワーカー2つ（`127.0.0.1:8000`） |
| 設定 | `.env` の `APP_ENV=development`・`FLASK_DEBUG=1` | `APP_ENV=production`（Dockerfile）、値は compose.yaml から |
| データベース | `instance/app.db` | ボリューム `db-data` の `/app/instance/app.db` |
| セッション | `instance/sessions/`（`REDIS_URL` 未設定時） | Redis（ボリューム `redis-data`） |
| 回数制限の記録 | メモリ（`REDIS_URL` 未設定時） | Redis |
| デバッグツールバー | 表示（`FLASK_DEBUG=1`） | なし（開発用の依存はイメージに入れない） |

### Dockerfile

- 2段階のビルド。1段目で uv を使い、`uv.lock` どおりに依存パッケージとアプリを `.venv` に入れる（開発用の依存は入れない）。2段目は `.venv`・`migrations/`・`entrypoint.sh` だけをコピーした小さなイメージ。
- 依存パッケージを先に入れるので、コードだけを変えたときは依存のインストールにキャッシュが効く。
- root ではない専用ユーザー `app` で動かす。

### compose.yaml

- `web`：Dockerfile からビルドしたアプリ。`127.0.0.1:8000` で自分のパソコンからだけ開ける。`SECRET_KEY` は `.env` から渡し、なければ起動しない。
- `redis`：セッションと回数制限の保存先。AOF でディスクにも書き、メモリの上限は 128MB（`docs/01.md` の7章）。

## 10. 開発ツールと品質チェック

| ツール | 内容 | 設定 | 動くタイミング |
| --- | --- | --- | --- |
| uv | 依存パッケージと Python の管理 | `pyproject.toml`・`uv.lock`・`.python-version` | — |
| ruff | lint と整形 | `pyproject.toml` の `[tool.ruff]` | pre-commit・CI |
| mypy | 型チェック（`src/`・`tests/`、型注釈を必須にする厳しめの設定） | `[tool.mypy]` | pre-commit・CI |
| djlint | テンプレートの整形と lint | `[tool.djlint]` | pre-commit |
| pytest | 自動テスト（CI ではカバレッジも測る） | `[tool.pytest.ini_options]` | pre-push・CI |

- pre-commit：コミットの前に ruff（修正→整形→確認）・djlint（整形→lint）・mypy、プッシュの前に pytest を動かす。
- CI（`.github/ci.yml`）：push と Pull Request で、ruff・mypy・pytest を実行し、テスト結果の集計を GitHub の画面に出す。ただし GitHub Actions が実行するのは `.github/workflows/` の中のファイルだけなので、今の置き場所では動かない。
