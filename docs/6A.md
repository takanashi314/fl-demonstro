# docker compose up --buildの流れA：Composeが設定を読む（6A）

`docs/06.md`のA（1〜6）を詳しくしたもの。

コードブロックの1行目に、抜き出したファイルと行番号を書いている。

ライブラリのコードは`.venv/lib/python3.15/site-packages/`からの相対パスで書く。

コードは、iPhoneの縦画面で読めるよう、改行やインデントを変えている（中身は同じ）。長いコメントは折り返すか省いている。

出力は、2026-11-22に手元で実行して取ったもの（Docker Compose v5.5.0）。

## 全体像

Aの段階でComposeがすることは、「ファイルを読み、値を置き換え、形をそろえ、確かめる」まで。

この段階では、まだ何も作らない（イメージ・ネットワーク・ボリューム・コンテナはどれもB以降）。

設定が分かりにくいのは、値が4つのファイルに分かれていて、読むものもタイミングも違うから。

- **`.env`**
  - 読むもの：Compose（`${...}`の置き換えの材料）と、手元で動かす`flask`コマンド
  - タイミング：A
- **`compose.yaml`**
  - 読むもの：Compose
  - タイミング：A
- **`Dockerfile`・`.dockerignore`**
  - 読むもの：BuildKit（イメージのビルド）
  - タイミング：B（ビルド）
- **`src/fl_demonstro/config.py`**
  - 読むもの：コンテナの中のPython
  - タイミング：F・G（importするとき）

前半（1〜4章）でComposeの処理を順に追い、後半（5〜6章）で、値がどのファイルからどこへ流れるかを追う。

7章では、値を受け取る側の`src/fl_demonstro/__init__.py`が、importされてからアプリを返すまでを追う。

## 1. compose.yamlを探す

1. Composeは、今いるフォルダでComposeファイルを探す。\
   名前は`compose.yaml`（推奨）・`compose.yml`・`docker-compose.yaml`・`docker-compose.yml`のどれか。
2. 見つからなければ、親のフォルダへ順にたどって探す。

```text
$ cd docs
$ docker compose config | head -1
name: fl-demonstro
```

（`docs/`の中で実行しても、プロジェクト直下の`compose.yaml`が読まれた）

3. 見つかった`compose.yaml`のあるフォルダが、プロジェクトのフォルダになる。\
   `build: .`の`.`や`.env`の場所は、ここを基準にする。

## 2. .envを読んで値を置き換える

### .envを読む

4. プロジェクトのフォルダの`.env`を読む（`--env-file`で別のファイルにもできる）。
5. 書き方は`名前=値`を1行に1つ。`#`で始まる行はコメント。

`.env`のひな形（手元の`.env`も同じ項目で、`SECRET_KEY`に値が入っている）：

```sh
# .env.example:7-19
# Flask アプリの場所
FLASK_APP=fl_demonstro

# 使う設定（development / production）。
# 未設定なら production。
APP_ENV=development

# デバッグモード（1 で有効）。
# 本番では書かないか 0 にすること。
FLASK_DEBUG=1

# （秘密の鍵の作り方の説明は省略）
SECRET_KEY=
```

6. 読んだ値は、`compose.yaml`の`${...}`を置き換える材料になる。

`compose.yaml`の中で`${...}`として使っているのは`SECRET_KEY`だけ。

```yaml
# compose.yaml:26-28
environment:
  # .env の SECRET_KEY を渡す（未設定ならエラーで止める）
  SECRET_KEY: ${SECRET_KEY:?SECRET_KEY
    を .env に設定してください}
```

そのため、`.env`の`FLASK_APP`・`APP_ENV`・`FLASK_DEBUG`は、Composeからは何にも使われない。\
この3つは、手元で`flask run`するときに`flask`コマンドが読むためのもの（6章）。

### 置き換える

7. `${名前...}`の部分を、値で置き換える。
8. 値を探す順番は、シェルの環境変数 → `.env`。\
   同じ名前が両方にあれば、シェルの値が使われる。

```text
$ SECRET_KEY=from-shell docker compose config
...
      SECRET_KEY: from-shell
```

9. 書き方によって、値がないときの動きが変わる。
   - `${名前}`：なければ空文字になる（警告が出る）。
   - `${名前:-既定値}`：ない、または空なら既定値になる。
   - `${名前:?メッセージ}`：ない、または空ならエラーで止まる。\
     このプロジェクトはこれを使っている。
   - `${名前?メッセージ}`：ないときだけエラーで止まる（空ならそのまま）。
10. `SECRET_KEY`が空なら、ここで止まる。\
    まだ何も作っていないので、途中まで作られたコンテナなどは残らない。

```text
$ SECRET_KEY= docker compose config
error while interpolating
services.web.environment.SECRET_KEY: required variable
SECRET_KEY is missing a value:
SECRET_KEY を .env に設定してください
```

（出力は折り返している）

置き換える前の形は、`docker compose config --no-interpolate`で見られる。

### .envはコンテナに渡らない

11. `.env`の中身が、自動でコンテナの環境変数になるわけではない。\
    コンテナに渡るのは、`compose.yaml`の`environment:`（と`env_file:`）に書いたものだけ。\
    このプロジェクトでは、次の3つ（4つ目はコメント）。

```yaml
# compose.yaml:26-35
environment:
  SECRET_KEY: ${SECRET_KEY:?SECRET_KEY
    を .env に設定してください}
  REDIS_URL: redis://redis:6379/0
  SESSION_COOKIE_SECURE: "false"
  # TRUSTED_PROXY_COUNT: "1"
```

（コメントは省略）

12. `.env`は`.dockerignore`にも書いてあるので、イメージにも入らない。

```text
# .dockerignore:1-2
# イメージに入れないもの（秘密情報・ローカルの作業ファイルなど）
.env
```

そのため、手元の`.env`の`APP_ENV`・`FLASK_DEBUG`は、コンテナの中には届かない。\
コンテナの`APP_ENV`は、`Dockerfile`の`ENV`で決まる（5章）。

## 3. プロジェクト名を決める

13. プロジェクト名は、次の順で最初に見つかったものになる。
    1. `docker compose -p 名前`
    2. 環境変数`COMPOSE_PROJECT_NAME`（`.env`に書いても効く）
    3. `compose.yaml`の`name:`
    4. プロジェクトのフォルダの名前
14. このプロジェクトは`name:`を書いているので、`fl-demonstro`になる。

```yaml
# compose.yaml:9-11
# プロジェクト名を固定する。
# 書かないとフォルダ名が使われるため、フォルダ名を変えると
# データの置き場所（ボリューム）の名前まで変わり、
# 前のデータが見えなくなってしまう。
name: fl-demonstro
```

15. プロジェクト名は、Dockerに作るものの名前の頭に付く。
    - ネットワーク：`fl-demonstro_default`
    - ボリューム：`fl-demonstro_db-data`・`fl-demonstro_redis-data`
    - コンテナ：`fl-demonstro-web-1`・`fl-demonstro-redis-1`
    - ビルドしたイメージ：`fl-demonstro-web`
16. 名前が変わると、別のプロジェクトとして扱われる。

```text
$ COMPOSE_PROJECT_NAME=other docker compose config
name: other
...
    name: other_default
...
    name: other_db-data
```

（出力の一部）

ボリュームの名前が`other_db-data`になり、前のデータ（`fl-demonstro_db-data`）が見えなくなる。\
`name:`を固定しているのは、フォルダ名を変えたときにこれが起きないようにするため。

## 4. 形をそろえて確かめる

### 短い書き方を、長い書き方にそろえる

17. Composeは、短い書き方をすべて決まった形（長い書き方）に直してから扱う。\
    直した結果は`docker compose config`で見られる。

ports：

```yaml
# compose.yaml:20-23
ports:
  # 自分のパソコンからだけ開けるようにする
  - "127.0.0.1:8000:8000"
```

```yaml
# docker compose config の出力
ports:
  - mode: ingress
    host_ip: 127.0.0.1
    target: 8000
    published: "8000"
    protocol: tcp
```

volumes：

```yaml
# compose.yaml:36-39
volumes:
  # データベース（SQLite）をコンテナの外に保存する
  - db-data:/app/instance
```

```yaml
# docker compose config の出力
volumes:
  - type: volume
    source: db-data
    target: /app/instance
    volume: {}
```

depends_on：

```yaml
# compose.yaml:42-43
depends_on:
  - redis
```

```yaml
# docker compose config の出力
depends_on:
  redis:
    condition: service_started
    required: true
```

18. `depends_on`の短い書き方は、`condition: service_started`（コンテナが起動したら次へ）になる。\
    Redisが接続を受け付けられるか（`service_healthy`）までは待たない（`docs/06.md`の38）。
19. どのサービスにも`networks: default`が足される。\
    `compose.yaml`にネットワークを書いていないので、全サービスが既定のネットワーク1つにつながる。
20. `build: .`は、プロジェクトのフォルダの絶対パスと`dockerfile: Dockerfile`になる。
21. トップレベルの`volumes:`・`networks:`には、実際の名前（プロジェクト名付き）が入る。

```yaml
# compose.yaml:71-73
volumes:
  db-data:
  redis-data:
```

```yaml
# docker compose config の出力
networks:
  default:
    name: fl-demonstro_default
volumes:
  db-data:
    name: fl-demonstro_db-data
  redis-data:
    name: fl-demonstro_redis-data
```

### 確かめる

22. 書き方の誤り（知らないキー、型の違いなど）があれば、ここでエラーにする。
23. サービスが使う名前付きボリュームが、トップレベルの`volumes:`に書かれているかを確かめる（書いていなければエラー）。
24. `depends_on`から、サービスの依存関係を組み立てる。\
    `web` → `redis`なので、起動はredisが先、止めるときはwebが先になる。\
    循環していればエラー。

### ここまでの結果

25. Aの段階の結果は「解釈済みの設定」1つだけで、Dockerにはまだ何も作っていない。
26. この結果をもとに、B（イメージの用意）以降が動く。
27. `docker compose config`は、Aだけを実行して結果を表示するコマンド。\
    ただし、置き換えた後の`SECRET_KEY`もそのまま表示されるので、出力を人に見せるときは注意する。

## 5. 値がどこから来て、どこへ行くか

ここからは、コンテナの中で使われる設定値を1つずつ追う。

コンテナの環境変数は、次の2つを合わせたものになる（同じ名前なら`compose.yaml`が優先）。

- イメージの`ENV`（`Dockerfile`で設定。ビルドのときに決まる）
- `compose.yaml`の`environment:`（Aで決まる）

```dockerfile
# Dockerfile:156-161
ENV PATH="/app/.venv/bin:$PATH" \
    PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    FLASK_APP=fl_demonstro \
    APP_ENV=production \
    INSTANCE_PATH=/app/instance
```

Dockerは、ほかに`HOSTNAME`や`HOME`（実行ユーザーのホームディレクトリ。`/home/app`）も足す。

### SECRET_KEY

`.env` → `compose.yaml` → 環境変数 → `config.py` → `app.config` → 拡張機能、と流れる。

1. 手元の`.env`に書く（ひな形では空）。

```sh
# .env.example:19
SECRET_KEY=
```

2. Aで、Composeが置き換える（2章）。

```yaml
# compose.yaml:28
SECRET_KEY: ${SECRET_KEY:?SECRET_KEY
  を .env に設定してください}
```

3. webコンテナの環境変数になる。
4. `config.py`がimportされたとき、クラスの属性に入る（`docs/06.md`の61）。

```python
# src/fl_demonstro/config.py:58
SECRET_KEY = os.environ.get("SECRET_KEY")
```

5. `create_app()`の`from_object()`で`app.config["SECRET_KEY"]`にコピーされ、値があるかを確かめる。

```python
# src/fl_demonstro/__init__.py:119-128

# 設定クラスの大文字の属性を app.config に読み込む

# （コメントは省略）

    raise RuntimeError(
        "SECRET_KEY が設定されていません。"
        ".env に SECRET_KEY=... を書いてください。"

```

6. Flask-WTFが、CSRFトークンの署名に使う（`current_app.secret_key`は`app.config["SECRET_KEY"]`と同じもの）。

```python

    secret_key,
    "WTF_CSRF_SECRET_KEY",
    current_app.secret_key,

```

7. Flask-Loginが、「ログインしたままにする」のCookieの署名に使う。

```python

```

### REDIS_URL

`compose.yaml` → 環境変数 → `config.py` → `app.config` → セッションと回数制限、と流れる。`.env`は通らない。

1. `compose.yaml`に値を直接書いている。\
   ホスト名の`redis`は、`compose.yaml`のサービス名（DockerのDNSがredisコンテナのIPアドレスに変換する）。

```yaml
# compose.yaml:31
REDIS_URL: redis://redis:6379/0
```

2. webコンテナの環境変数になる。
3. `config.py`のimportで、`REDIS_URL`に入る。\
   同じクラスの中の`RATELIMIT_STORAGE_URI`も、このときにRedisのURLになる。

```python
# src/fl_demonstro/config.py:66
REDIS_URL = os.environ.get("REDIS_URL")
```

```python
# src/fl_demonstro/config.py:109-111
RATELIMIT_STORAGE_URI = (
    os.environ.get("RATELIMIT_STORAGE_URI")
    or REDIS_URL
    or "memory://"
)
```

4. `from_object()`で`app.config`にコピーされる。
5. `create_app()`の`_configure_session_storage()`が、セッションの保存先をRedisにする。

```python
# src/fl_demonstro/__init__.py:55-60
if app.config.get("SESSION_TYPE"):
    # テスト用の設定などで指定済み
    return
if redis_url := app.config.get("REDIS_URL"):
    # Redis に保存する
    app.config["SESSION_TYPE"] = "redis"
    app.config["SESSION_REDIS"] = Redis.from_url(redis_url)
```

6. Flask-Limiterが、`init_app()`で`RATELIMIT_STORAGE_URI`を読み、回数の記録先にする。

```python
# flask_limiter/_extension.py:360
storage_uri_from_config = config.get(
    ConfigVars.STORAGE_URI, None
)
```

（`ConfigVars.STORAGE_URI`は`"RATELIMIT_STORAGE_URI"`）

### SESSION_COOKIE_SECURE

`compose.yaml` → 環境変数 → `config.py`（`_env_bool()`）→ CookieとHSTS、と流れる。

1. `compose.yaml`に`"false"`と書いている。\
   環境変数は文字列なので、引用符で囲んで文字列として渡している。

```yaml
# compose.yaml:32-33
# ローカルの http://localhost で試すため。
# HTTPS で公開するときは消すこと。
SESSION_COOKIE_SECURE: "false"
```

2. webコンテナの環境変数になる。
3. `config.py`のimportで、`_env_bool()`が文字列を真偽値にする。\
   `"1"`・`"true"`・`"yes"`・`"on"`だけが`True`。`"false"`は`False`。

```python
# src/fl_demonstro/config.py:24-33
def _env_bool(name: str, default: bool) -> bool:
    """（docstring は省略）"""
    value = os.environ.get(name)
    if value is None:
        return default
    return value.strip().lower() in (
        "1",
        "true",
        "yes",
        "on",
    )
```

```python
# src/fl_demonstro/config.py:186-201
class ProductionConfig(Config):
    """（docstring は省略）"""

    # （コメントは省略）
    SESSION_COOKIE_SECURE = _env_bool(
        "SESSION_COOKIE_SECURE", True
    )
    # 「ログインしたままにする」の Cookie も、
    # 上の行と同じ値にそろえる
    REMEMBER_COOKIE_SECURE = SESSION_COOKIE_SECURE
```

4. Cookieを出すとき、`Secure`を付けない（httpのlocalhostでもログインできる）。
5. `security.py`が、HSTSヘッダーを付けない。

```python
# src/fl_demonstro/security.py:49-53
if app.config["SESSION_COOKIE_SECURE"]:
    # HTTPS で運用しているときだけ、
    # 今後も HTTPS を使うようブラウザに伝える
    response.headers["Strict-Transport-Security"] = (
        "max-age=31536000; includeSubDomains"
    )
```

6. HTTPSで公開するときは、`compose.yaml`からこの行を消す。\
   未設定なら`_env_bool()`の既定値の`True`になる。

### APP_ENV

`Dockerfile`の`ENV`（156〜161行目）で`production`に決まり、`get_config()`が`ProductionConfig`を選ぶ。

```python
# src/fl_demonstro/config.py:251-262
def get_config(name: str | None = None) -> type[Config]:
    """（docstring は省略）"""
    # name が空文字のときも、未指定と同じく APP_ENV を見る
    name = name or os.environ.get("APP_ENV", "production")
```

`create_app()`は引数なしで呼ばれる（`flask`コマンドからもgunicornからも）ので、`config_class or get_config()`（上の`__init__.py:119-128`）で`get_config()`が使われる。

手元の`.env`の`APP_ENV`（ひな形では`development`）は、2章のとおりコンテナには届かない。

### DATABASE_URL

`.env`・`compose.yaml`・`Dockerfile`のどこにもないので、既定値が使われる。

```python
# src/fl_demonstro/config.py:63
SQLALCHEMY_DATABASE_URI = os.environ.get(
    "DATABASE_URL", "sqlite:///app.db"

```

Flask-SQLAlchemyが、相対パスをinstanceフォルダからの位置にする。

```python
# flask_sqlalchemy/extension.py:626-628

    os.makedirs(app.instance_path, exist_ok=True)
    db_str = os.path.join(app.instance_path, db_str)
```

その場所（`/app/instance/app.db`）には`db-data`ボリュームが付いているので、DBのファイルはコンテナを作り直しても残る。

### 環境変数ではない設定

`compose.yaml`の残りの項目は、アプリではなくDockerが使う。

- `build`・`image`：B（イメージの用意）
- `volumes`・`ports`・`restart`・`depends_on`：C・D（作成と起動）
- `command`（redis）：E（Redisの起動）

## 6. 手元とDockerの違い

同じ`.env`を使っていても、手元で`flask run`するときと、`docker compose up`するときとでは、設定の入り方が違う。

### 手元でflask runするとき

1. `flask`コマンドが、`.env`の中身を環境変数に入れる（python-dotenv）。\
   すでにシェルで設定されている名前は上書きしない。

```python

    """Load "dotenv" files to set environment variables.
    A given path takes precedence over ``.env``, which
    takes precedence over ``.flaskenv``. After loading and
    combining these files, values are only set if the key
    is not already set in ``os.environ``.
    ..."""
```

（型ヒントは省略）

2. `APP_ENV`・`FLASK_DEBUG`・`SECRET_KEY`などが、そのまま`config.py`とFlaskに届く（ひな形どおりなら、開発用の設定とデバッグモード）。
3. `REDIS_URL`がないので、セッションは`instance/sessions`のファイル、回数の記録はメモリになる。

### docker compose upするとき

1. Composeは、`.env`を`${...}`の置き換えにだけ使う。
2. コンテナに届くのは、`compose.yaml`の`environment:`の3つと、`Dockerfile`の`ENV`。
3. `APP_ENV`は`production`、`FLASK_DEBUG`はなし、`REDIS_URL`はあり。

### 流れの図

```text
【手元】
.env
 └─ flask コマンドが全部読む
     └─ config.py

【Docker】

     └─ compose.yaml

     └─ app.config
         （create_app）
```

## 7. __init__.pyの動き

### _instance_path()

コードは5章のINSTANCE_PATH。
