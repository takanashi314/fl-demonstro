# docker compose up --buildの流れF：webが起動し、マイグレーションを流す（6F）

`docs/06.md`のF（55〜82）を詳しくしたもの。

コードブロックの1行目に、抜き出したファイルと行番号を書いている。

ライブラリのコードは`.venv/lib/python3.15/site-packages/`からの相対パスで書く（コンテナの中では`/app/.venv/lib/python3.15/site-packages/`）。

コードやログは、iPhoneの縦画面で読めるよう、改行やインデントを変えたり、一部を省いたりしている。

出力は、2026-11-27に手元で実行して取ったもの。ログの時刻はUTC（日本時間の9時間前）。

`create_app()`の中身は`docs/6A.md`の7章に書いたので、ここでは、その前後（`entrypoint.sh`・`flask`コマンド・Alembic）を追う。

## 全体像

```text
PID 1: sh entrypoint.sh gunicorn ...（appユーザー）
 ├ 子プロセス: flask db upgrade
 │  ├ .envを探す（ない）
 │  ├ create_app()（docs/6A.mdの7章）
 │  ├ Alembic → migrations/env.py
 │  │  → /app/instance/app.dbに接続
 │  └ 終了ステータス0で終わる
 └ exec → PID 1: gunicorn（docs/6G.md）
```

この段階では、Redisに一度もつながない。\
起動の間、Redisで`MONITOR`を動かしておいても、コマンドは1つも届かなかった（別のプロジェクト名で試した）。

## 1. ボリュームとプロセス

1. `db-data`ボリュームを`/app/instance`に付ける。
2. ボリュームが空なら、イメージの`/app/instance`の中身と所有者がコピーされる。\
   「新しく作ったボリューム」ではなく「空のボリューム」が条件で、中身があればコピーしない。\
   イメージの`/app/instance`は`app:app`（`Dockerfile`の138行目）なので、空のボリュームなら`app`ユーザーがDBのファイルを作れる。

```text
（空のボリューム）
drwxr-xr-x 2 999 999 ... /app/instance

（rootの持ち物のファイルを置いたボリューム）
drwxr-xr-x 2 0   0   ... /app/instance
-rw-r--r-- 1 0   0   ... keep
touch: cannot touch '/app/instance/x':
  Permission denied
```

（`docker volume create`で作ったボリュームを、`fl-demonstro-web`のイメージのコンテナに付けて確かめた）

3. 今回のボリュームには、11-21に作った`app.db`（`app:app`）がすでにあるので、何もコピーされない。
4. Dockerは、イメージの設定（`docs/6D.md`の8）からプロセスを作る。
   - 実行ファイル：`entrypoint.sh`。パスではないので`PATH`から探し、`/usr/local/bin/entrypoint.sh`が見つかる。
   - ユーザー：`app`。イメージの`/etc/passwd`から、uid 999・gid 999になる。
   - 作業フォルダ：`/app`。
   - 引数：`CMD`の8つの要素。
5. カーネルは、ファイルの1行目`#!/bin/sh`を見て、`/bin/sh /usr/local/bin/entrypoint.sh gunicorn --bind ...`として実行する。\
   `python:3.15-slim`（Debian）の`/bin/sh`は`dash`。
6. このshがPID 1になり、`CMD`の8つの要素が`$1`〜`$8`になる。\
   `Init`を使っていない（`docs/6D.md`の16）ので、shとコンテナの間に、ほかのプロセスはない。

## 2. entrypoint.sh

```sh
# docker/entrypoint.sh:1-8
#!/bin/sh
# （コメントは省略）
set -e

flask db upgrade

exec "$@"
```

7. `set -e`：終了ステータスが0以外のコマンドがあると、そこでスクリプトを終える。
8. `flask db upgrade`：子プロセスとして実行し、終わるのを待つ（3〜5章）。
9. `flask db upgrade`が失敗すると、shがその終了ステータスで終わる。\
   PID 1が終わるのでコンテナが止まり、`restart: unless-stopped`でDockerが起動し直す。\
   別のプロジェクト名で`APP_ENV: bogus`を足して試すと、`get_config()`の`ValueError`で止まり、起動し直しを繰り返した。

```text
ValueError: APP_ENV の値 'bogus' は使えません
  （development, production のどれか）。
```

`ValueError`が出た時刻（7回分）：

```text
21:34:16.941
21:34:18.727  （+1.8秒）
21:34:20.457  （+1.7秒）
21:34:22.342  （+1.9秒）
21:34:24.106  （+1.8秒）
21:34:27.174  （+3.1秒）
21:34:31.875  （+4.7秒）
```

10. 間隔は、「起動してから失敗するまで（約1.7秒）」と「Dockerが起動し直すまでの待ち時間」の合計。\
    待ち時間は100ミリ秒から倍々に増え（上限は1分）、コンテナが10秒以上動けば100ミリ秒に戻る。
11. この間、`docker compose ps`のwebは`Restarting (1)`（`1`は前回の終了ステータス）になり、gunicornは一度も起動しない。\
    `docker compose up -d`は、コンテナを起動できた時点で成功として終わるので、これに気づくにはログを見る。
12. 失敗しなければ、最後の`exec "$@"`に進む（6章）。

## 3. flaskコマンドが起動する

13. `flask`は`PATH`の先頭の`/app/.venv/bin/flask`。\
    1行目が`#!/app/.venv/bin/python`なので、仮想環境の`python`（`/usr/local/bin/python3`へのシンボリックリンク）で実行される。
14. Pythonは、実行ファイルの1つ上のフォルダにある`pyvenv.cfg`を見て、`sys.prefix`を`/app/.venv`にし、その`site-packages`を`sys.path`に足す。\
    `uv run`も`activate`もなしで、仮想環境のパッケージが使われるのはこのため。

```text
$ python -c "import sys; print(sys.path)"
['', '/usr/local/lib/python315.zip',
 '/usr/local/lib/python3.15',
 '/usr/local/lib/python3.15/lib-dynload',
 '/app/.venv/lib/python3.15/site-packages']
```

（コンテナの中で実行した。`-c`なので、先頭は作業フォルダを表す空文字）

`/app/src`のような場所は入っていないので、`fl_demonstro`はsite-packagesにコピーされたもの（`docs/6B.md`の37）が使われる。

### .envを探す

```python
# flask/cli.py:755-769
if load_defaults:
    for default_name in (".flaskenv", ".env"):
        if not (
            default_path := dotenv.find_dotenv(
                default_name, usecwd=True
            )
        ):
            continue

        data |= dotenv.dotenv_values(
            default_path, encoding="utf-8"
        )

if path is not None and os.path.isfile(path):
    data |= dotenv.dotenv_values(path, encoding="utf-8")

for key, value in data.items():
    if key in os.environ or value is None:
        continue

    os.environ[key] = value
```

15. python-dotenvが入っているので、`flask`コマンドは、コマンドを探す前に`.flaskenv`と`.env`を探す。
16. `find_dotenv(..., usecwd=True)`は、作業フォルダ（`/app`）から親のフォルダへ順にたどる。\
    `/app/.flaskenv`・`/.flaskenv`・`/app/.env`・`/.env`のどれもないので、何も読まない（`.env`は`.dockerignore`でビルドコンテキストにも入れていない）。
17. 見つかったとしても、すでに環境変数にある名前は上書きしない（`if key in os.environ`）。

### dbコマンドを探す

```python
# flask/cli.py:617-642
def get_command(self, ctx, name):
    self._load_plugin_commands()
    rv = super().get_command(ctx, name)

    if rv is not None:
        return rv

    info = ctx.ensure_object(ScriptInfo)

    try:
        app = info.load_app()
    except NoAppException as e:
        click.secho(
            f"Error: {e.format_message()}\n",
            err=True,
            fg="red",
        )
        return None

    if not current_app or (
        current_app._get_current_object() is not app
    ):
        ctx.with_resource(app.app_context())

    return app.cli.get_command(ctx, name)
```

（型ヒントとコメントは省略）

18. `db`は、Flaskに組み込みのコマンド（`run`・`shell`・`routes`）でも、プラグインのコマンドでもない。\
    Flask-Migrateは`db`を`init_app()`のときに`app.cli`に足す（`docs/6A.md`の7章の26）ので、アプリを読み込まないと見つからない。
19. そのため`info.load_app()`で、`FLASK_APP=fl_demonstro`をimportして`create_app()`を呼ぶ（`docs/6A.md`の7章）。\
    `flask db upgrade`は、マイグレーションの前に必ず`create_app()`を1回通る。
20. `create_app()`で例外が出たときの動きは、例外の種類で分かれる。
    - `NoAppException`（アプリが見つからないなど）：赤い`Error:`を出し、`None`を返す。Clickは`No such command 'db'`として終了ステータス2で終わる。
    - それ以外（9の`ValueError`など）：捕まえないので、トレースバックを出して終了ステータス1で終わる。
21. アプリコンテキストを開いてから（`ctx.with_resource(app.app_context())`）、`app.cli`の中の`db`を返す。\
    この後のFlask-Migrateと`migrations/env.py`は、`current_app`でこのアプリを使う。
22. `create_app()`の中では、DBのエンジンも、Redisのクライアント（セッション用と回数制限用）も作るが、どれも接続はしない。\
    回数制限のライブラリ（limits）は、Luaスクリプトを`register_script()`で登録するが、これはスクリプトのSHA1を手元で計算するだけで、Redisには送らない。

## 4. Flask-MigrateからAlembicへ

```python
# flask_migrate/__init__.py:107-115
def catch_errors(f):
    @wraps(f)
    def wrapped(*args, **kwargs):
        try:
            f(*args, **kwargs)
        except (CommandError, RuntimeError) as exc:
            log.error('Error: ' + str(exc))
            sys.exit(1)
    return wrapped
```

```python
# flask_migrate/__init__.py:195-200
@catch_errors
def upgrade(directory=None, revision='head', sql=False,
            tag=None, x_arg=None):
    """Upgrade to a later version"""
    config = current_app.extensions[
        'migrate'
    ].migrate.get_config(directory, x_arg=x_arg)
    command.upgrade(config, revision, sql=sql, tag=tag)
```

23. `flask db upgrade`の引数がないので、`revision='head'`（最新）まで上げる。
24. AlembicのエラーとRuntimeErrorは、`catch_errors`が`Error: ...`のログにして、終了ステータス1で終わらせる。\
    それ以外の例外（SQLiteのエラーなど）は、トレースバックになる。どちらでも、`entrypoint.sh`の`set -e`で止まる。

```python
# flask_migrate/__init__.py:84-89
def get_config(self, directory=None, x_arg=None,
               opts=None):
    if directory is None:
        directory = self.directory
    directory = str(directory)
    config = Config(os.path.join(directory, 'alembic.ini'))
    config.set_main_option('script_location', directory)
```

25. `self.directory`は既定の`'migrations'`で、作業フォルダからの相対パス。\
    `WORKDIR /app`なので`/app/migrations/alembic.ini`になり、`Dockerfile`の`COPY migrations ./migrations`の置き場所と合う。
26. Alembicの`command.upgrade()`は、`migrations/versions/`の3つのファイルを読んで、版のつながりを組み立てる。

```text
d96ac129be18  create users table
 └ e7469dcb534f  make username unique
                 case-insensitively
    └ 85dd7755e1ac  store usernames in lowercase
                    only（head）
```

（各ファイルの`down_revision`が、1つ前の版を指す）

27. その後、`migrations/env.py`を実行する。\
    `migrations/`と`versions/`の`.py`は、`PYTHONDONTWRITEBYTECODE=1`で、しかもrootの持ち物なので、`.pyc`は作られず、毎回コンパイルされる（小さいので問題にならない）。

    `%(levelname)-5.5s`は「5文字に切って、5文字になるまで右に空白を足す」なので、`INFO`の後ろに空白が2つ入る（`INFO  [alembic...]`）。
29. `sqlalchemy.engine`のロガーは`WARN`なので、実行したSQLはログに出ない。

```python

    context.configure(
        connection=connection,
        target_metadata=get_metadata(),
        **conf_args
    )

    with context.begin_transaction():
        context.run_migrations()
```

30. `get_engine()`は、`current_app.extensions['migrate'].db.engine`（`migrations/env.py:23`）。\
    `create_app()`の`db.init_app()`で作ったエンジン（`sqlite:////app/instance/app.db`）を、そのまま使う。
31. `connect()`で、ここで初めてSQLiteのファイルを開く。\
    ファイルがなければ作るので、`/app/instance`に書き込めないと、ここで失敗する（2のボリュームの所有者が効くのはここ）。

### Alembicがマイグレーションを流す

```python
if self.as_sql:

log.info(
```

32. `context.configure()`で作られる`MigrationContext`が、ログの最初の2行を出す。\
    SQLite用の実装（`SQLiteImpl`）は`transactional_ddl = False`なので、`non-transactional`になる。

```python
# alembic/runtime/migration.py:594-623
heads = self.get_current_heads()
...
    if not self.as_sql and not heads and not dont_mutate:
        self._ensure_version_table()

head_maintainer = HeadMaintainer(self, heads)

for step in self._migrations_fn(heads, self):
    with self.begin_transaction(_per_migration=True):

        head_maintainer.update_to_step(step)
```

（オフラインモードとコールバックの部分は省略）

33. `get_current_heads()`：`alembic_version`テーブルから、今の版を読む（テーブルがなければ「版なし」）。
34. 版がなければ、`_ensure_version_table()`で`alembic_version`テーブルを作る。
35. 今の版からheadまでの、未適用の版を1つずつ流す。\
    1つごとに`Running upgrade <前の版> -> <次の版>, <説明>`を出し、そのファイルの`upgrade()`を実行して、`alembic_version`を次の版に書き換える。

```python
# alembic/runtime/migration.py:409-413
if self.impl.transactional_ddl:
    transaction_now = (
        _per_migration == self._transaction_per_migration
    )
else:
    transaction_now = _per_migration is True
```

36. `non-transactional`なので、`env.py`の`with context.begin_transaction():`（`_per_migration`なし）は何もせず、版ごとの`begin_transaction(_per_migration=True)`がトランザクションを始めて、版ごとにコミットする。\
    2つ目の版で失敗しても、1つ目は適用済みのまま残り、`alembic_version`も1つ目の版になる。次の起動では、2つ目からやり直す。
37. 今回は、ボリュームのDBがすでにheadだったので、流す版はなく、ログは2行だけ。

新しいボリュームのとき（別のプロジェクト名で試した）：

```text
INFO  [alembic.runtime.migration] Context impl
  SQLiteImpl.
INFO  [alembic.runtime.migration] Will assume
  non-transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade
  -> d96ac129be18, create users table
INFO  [alembic.runtime.migration] Running upgrade
  d96ac129be18 -> e7469dcb534f, make username unique
  case-insensitively
INFO  [alembic.runtime.migration] Running upgrade
  e7469dcb534f -> 85dd7755e1ac, store usernames in
  lowercase only
```

38. 3つの版がしていること。
    - `d96ac129be18`：`users`テーブルと、`username`の重複禁止のインデックス`ix_users_username`を作る。
    - `e7469dcb534f`：`lower(username)`の式インデックス`uq_users_username_lower`を作り、`ix_users_username`を消す。
    - `85dd7755e1ac`：`username`を小文字にそろえ（`UPDATE`）、`ix_users_username`を作り直し、式インデックスを消す。
39. 新しいDBでも、最後の形にいきなり作るのではなく、3つを順に流す。\
    途中で式インデックスを作ってすぐ消すことになるが、どの版から上げても同じ結果になるのは、この流し方のおかげ。
40. 流した後のDB（`sqlite_master`）：

```text
table alembic_version
  version_num VARCHAR(32) NOT NULL  -- 主キー
table users
  id INTEGER NOT NULL               -- 主キー
  username VARCHAR(64) NOT NULL
  password_hash VARCHAR(256) NOT NULL
  created_at DATETIME NOT NULL
index ix_users_username ON users (username)  UNIQUE
```

（`alembic_version`の行は`85dd7755e1ac`の1つ）

## 5. flaskコマンドが終わる

41. マイグレーションが終わると、Clickがコマンドを終え、開いていたアプリコンテキストを閉じる。\
    `teardown_appcontext`に登録された、Flask-SQLAlchemyのセッションを閉じる処理が動く。
42. `flask`のプロセスは、終了ステータス0で終わる。\
    このプロセスで作ったアプリ・エンジン・Redisのクライアントは、プロセスと一緒に消える。\
    gunicornのワーカーは、これとは別に、もう一度`create_app()`を呼ぶ（`docs/6G.md`の5章）。

## 6. exec "$@"

43. `"$@"`は、`$1`〜`$8`を、1つずつ別の引数のまま並べる。\
    `fl_demonstro:create_app()`の`()`のような記号も、そのまま1つの引数として渡る。
44. `gunicorn`はパスではないので、shが`PATH`の先頭の`/app/.venv/bin`から見つける。
45. `exec`は子プロセスを作らず、今のプロセス（PID 1のsh）の中身をgunicornに置き換える。\
    PIDは1のままで、環境変数・作業フォルダ・開いているファイル（標準出力と標準エラーのパイプ）も引き継ぐ。
46. `exec`を付けずに`"$@"`とだけ書くと、shがPID 1のまま残り、gunicornはその子になる。\
    `docker stop`のSIGTERMはPID 1のshにだけ届く。\
    PID 1のプロセスには、ハンドラーを登録していないシグナルは届かない（カーネルが捨てる）ので、shは何もせず、gunicornにも伝わらない。\
    10秒後にSIGKILLで全部が止められ、gunicornは処理中のリクエストを終える機会がない（`docs/6I.md`の2章）。
47. `exec`した後は、gunicornがPID 1として、SIGTERMのハンドラーを持ち（`docs/6G.md`の2章）、親のいなくなったプロセスの後始末（ゾンビの回収）も受け持つ。\
    gunicornの`reap_workers()`は`waitpid(-1)`で、ワーカーでない子も回収するように書かれている（`gunicorn/arbiter.py:640-643`のコメントに、PID 1で動くときのためとある）。

`exec`した後のwebのプロセス（`/proc`から読んだもの）：

```text
PID PPID UID CMD
  1    0 999 /app/.venv/bin/python
             /app/.venv/bin/gunicorn --bind ...
  8    1 999 （同じ。ワーカー）
  9    1 999 （同じ。ワーカー）
```

ここから先は`docs/6G.md`。
